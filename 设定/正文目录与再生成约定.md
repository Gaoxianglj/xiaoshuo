# 正文目录与再生成约定

> 建立：2026-08-13（作者在对话中确认）
> 用途：`正文/` 被清空后的再生成规则。新 Chat 读到本文件后，**无需再向作者确认"从 git 恢复旧稿还是重新生成"**，直接按既有流程再生成。

## 1. 背景与作者意图

- 作者于 2026-08-13 **主动删除** `正文/` 下的全部文件（含现行 Markdown 正文与 DOCX）；git 最后一次相关提交为"清理正文目录中的旧版文件（docx/md 迁移前旧稿）"。
- 作者意图：让写作 Agent 按项目既存流程，从逐章细纲**重新生成**正文 Markdown，用于对比再生成稿的写作文风与完成度。这不是误删，也**不需要从 git 历史恢复旧稿**。
- 再生成方式已由作者确认：按既有流程执行——细纲 → 连续性载荷 → 正文 → 文风回改 → 连续性检查 → 章节快照与追踪同步。

## 2. 再生成执行规则

1. 新 Chat 接到"重新生成第NNN章正文"的任务时，直接按 `AI_RULES.md`、`Bible.md`、`设定/文风.md` 与 `追踪/章节索引.md` 的流程执行，不再询问是否恢复旧稿。
2. 正文路径保持 `追踪/章节索引.md` 登记的现行映射不变（例如第001章为 `正文/正文MD/学院魔女_第一章_学院的新生.md`）。
3. 写作依据为对应细纲（`大纲/细纲_第NNN章.md`）与 `追踪/连续性/` 的载荷、快照及三张主表；再生成不得改变既有剧情节点、知情边界与物件状态。
4. 文风约束不变：001 仍只提供剧情与设定事实，**不作为文风样本**；002—008 为正向样本；009 仅作偏移校准。再生成稿在作者认可文风前，不得进入 `设定/文风锚点.md`。
5. 每章再生成完成后，按流程更新对应章节快照与 `追踪/上下文.md`。作者2026-08-15确认：**目前及之后无需生成 DOCX**，Markdown 为唯一阅读与交付格式；`AI_RULES.md` 第 8 节的 Word 流程仅作历史留存，不再默认执行。
