# Blender 执行与验收

## 1. 执行原则

在目标电脑实际执行。本文件不是已经测试过的 Blender 脚本，也不声称本包含有现成模型、贴图或成片。执行 AI 应根据已安装版本编写和测试脚本，使用界面或 Python API 均可。

单线程自主完成，按“构图 → 六时刻布光 → 连续性 → 成片”推进。常规技术选择自行判断并记录；不要停在教程、伪代码或只保存一个未渲染的工程。

## 2. 环境与工程

- 检查操作系统、Blender 实际版本与可执行文件路径、CPU、内存、GPU、可用渲染后端、显存及磁盘余量。不能把“检测到 GPU”当作“Cycles 已使用 GPU”。
- 使用本机可用的稳定版本；节点接口、色彩管理及 GPU 设置按实际版本查询。不要为了迎合猜测的 API 擅自升级现有环境。
- 创建独立目录 `stockton_autumn/`，所有输出放在其中。构建脚本重跑时只清理自己创建的场景集合，不删除其他项目或任意已有工程。
- 配置集中保存：随机种子、场景尺度、相机、分辨率、帧率、帧范围、质量档位、太阳曲线、雾密度、灯光强度、资源路径。固定布局随机种子，禁止每帧重抽树木、建筑或云的随机分布。
- 优先程序化材质和可复用网格。外部树木或贴图使用可明确再分发的资源，记录来源、作者、许可与修改；不擅自购买素材。无网络时用程序化资产继续制作。

建议交付结构：

```text
stockton_autumn/
  stockton_autumn.blend
  build_scene.py
  config.json
  assets/                 # 未内嵌的资源、许可与必要缓存
  previews/               # 六时刻图片、连续片段、完整低清预览
  frames/                 # 最终逐帧序列
  output/stockton_autumn.mp4
  RUN.md                  # 当前平台可复制的构建、渲染、续渲、编码命令
  REPORT.md               # 实测配置、帧耗时、视觉检查与已知限制
  ASSET_LICENSES.md
```

## 3. 建模与照明实现要点

### 场景组织

按 Terrain、Lake、Forest、Town、Foreground、Boats、Atmosphere、Lighting、Camera 分集合。渲染对象应有可理解的名字。

采用实例布置森林与建筑，近景精细、中景轮廓完整、远景简化。散布遮罩必须排除湖面、道路和建筑范围；树根、房屋底面贴合地形；湖岸不要出现穿帮直线。先按屏幕占比控制实例数量，禁止盲目堆百万真实网格。

### 日夜系统

- 优先使用 Cycles 完成最终光照。使用本机支持的物理天空与一个主太阳光，天空的太阳方向和主光方向由同一时间参数控制。
- 避免重复太阳能量：确认天空模型是否含太阳圆盘及直射贡献，选择明确的一套方案，不能把高强度 HDRI 太阳与独立 Sun 灯无校准叠加。
- 太阳能量在落山时平滑衰减；天空在黄昏后平滑过渡至夜间环境。不要假设某个白天天空节点会自动生成正确夜空。
- 近景叶片需要合适的透光或双面表现。水应有介电反射与合适粗糙度，水纹的尺度随世界单位匹配；不依赖自发光伪造湖光。
- 雾优先局部低密度体积。大场景使用错误的密度会变成实心白墙，先检查透视距离。资源不足时减小体积范围，远山可用克制的雾化合成辅助，但需检查反射一致性。
- 云优先低成本、稳定的程序化或适当层次的几何方案；太阳遮蔽、天空外观、水中反射要相容。不要只在最终画面贴一层快速滑动的白云图。
- 暖窗使用发光材质并按屏幕尺度决定是否添加少量真实灯。不要为每个遥远窗口创建高成本灯，也不要将发光面误当成必然能照亮附近环境。
- 色彩管理优先选本机可用的 AgX 或同类宽动态显示变换并记录；全片锁定同一套变换与白平衡，曝光仅作连续有限修正。

### 动画稳定性

太阳、天空、雾、云、水和灯光统一由时间参数派生，但可有各自平滑速度。驱动器或回调必须在重新打开工程与后台渲染中仍有效；更稳妥时把关键结果烘焙成关键帧。缓存路径相对化。

船走互不相撞的曲线，水纹随船，灯随船；日落后靠岸，不能穿码头、漂上陆地或凭空消失。七艘船的安排只需在傍晚辨认，不牺牲主要画面强行放大。

延时感来自一天的光与影流动；不要把相机快门模糊开到极大来模拟。默认先关闭运动模糊测试，再小幅加入；程序化水纹和阴影闪烁不能靠模糊掩盖。逐帧降噪并不自动保证时间稳定，必须检查连续片段。

## 4. 默认质量与性能测量

| 档位 | 输出 | 用途 |
|---|---|---|
| 构图草稿 | 960×540，低采样，静帧 | 检查空间、尺度与机位 |
| 动画预览 | 960×540，24 fps，全长；Cycles 低采样或 EEVEE | 检查节奏、漂移、亮度跳变；若用 EEVEE，标明不能代替 Cycles 光影验收 |
| 最终默认 | 1920×1080，24 fps，720 帧，Cycles | 30 秒正式动画；从 128 samples、自适应采样阈值约 0.02 开始试测，按噪点调整 |
| 可选升级 | 2560×1440 或 3840×2160 | 仅在1080p测试和耗时评估之后，按作者要求采用 |

上述采样参数是起点，不是画质保证。检查暗部、水面和体积再决定是否提升至 256 samples 或更高；不要为所有帧盲目使用极高采样。

至少测白天、夕阳、夜景三帧的最终设置耗时，包含一帧冷启动观察；记录实际 GPU/CPU 设备和显存使用情况。用实测平均每帧秒数 × 720 估算纯渲染时间，并注明场景加载、缓存、写盘及复杂时段造成的误差。例如每帧 20 秒约 4 小时、60 秒约 12 小时、180 秒约 36 小时，这只是算例，不是目标机器的承诺。

同时估算磁盘：实测平均每帧文件大小 × 720，加上资产、缓存和视频，并预留余量。

降档顺序：减少远景几何与不可见细节 → 降低云雾成本 → 优化实例和灯光 → 降至1280×720保持30秒与24fps。仍不可行时先交完整低清预览、工程和续渲指令，说明正式渲染未完成。不要静默缩短为几秒、改成静图或宣称预览为最终高质量成片。

## 5. 必须实际完成的阶段

1. **灰模**：建立地形、湖面、城镇体块和固定相机，输出一张图并亲自查看。修正湖被遮、城镇过小、山坡悬空等问题。
2. **关键时刻**：输出帧 1、97、265、553、625、720 共六张图并逐张查看。核对冷热、曝光、阴影方向、湖面反射与夜间层次。将六张组成联络表便于比较。
3. **连续测试**：至少渲染夕阳转蓝调的连续48帧和夜景连续48帧，检查闪烁、降噪涂抹、云层跳跃和窗灯突变。静帧好看不等于动画通过。
4. **全长预览**：实际生成并播放完整30秒低清片，检查时间变化是否连贯，是否由白天突然跳到夜晚。修正后记录结果。
5. **最终序列**：按测量可承受的正式档位生成帧序列。保存工程后，从后台或重新启动的 Blender 渲染至少一帧验证可复现，再批量执行。
6. **视频与交付**：从已验证序列编码 MP4；用播放器实际检查开头、中段、傍晚与结尾，报告完成程度与残留问题。

不必每阶段向作者再索要确认；给出可审阅预览并继续授权范围内的工作。若作者期间提出方向修改，先纳入再批量渲染。

## 6. 输出与恢复

先输出逐帧 PNG 或 OpenEXR，再编码 MP4，不以直接渲染视频作为唯一母版。默认采用已应用显示变换的 PNG 序列便于交付；若采用线性 EXR，必须在视频编码前正确应用同一显示变换，不能把线性 RGB 直接作为普通 sRGB 视频。

建议帧名 `stockton_0001.png` 至 `stockton_0720.png`。记录实际位深和色彩管理。MP4 优先 H.264、yuv420p、24 fps；若目标环境无 FFmpeg，使用 Blender 自带的视频编码功能并验证可播放。

RUN.md 中写出目标平台真实可执行的命令，包含指定工程、设备、帧范围与输出路径；不要只给占位路径。续渲应核对缺帧与损坏帧，不能把“文件存在”等同于有效。重渲后防止混入不同相机或不同调色版本的旧帧。

## 7. 最终验收表

- [ ] 地理能读成“南侧草坡 → 南岸城镇 → 大湖 → 北侧缓山”，两侧有森林山体。
- [ ] 草坡有大石，没有新增栏杆、观景亭或住宅。
- [ ] 建筑、船、树和水面尺度可信，没有漂浮、穿地、穿岸。
- [ ] 固定机位、焦距与地平线稳定；全片没有悄悄换景。
- [ ] 日出右侧、日落左侧，天空、投影与反射来自一致的照明。
- [ ] 上午、午间、夕阳、蓝调、夜晚可辨，色彩不过饱和，高光保留层次。
- [ ] 夜晚确实更暗，灯火有局部感，水与山仍可区分。
- [ ] 树林没有明显重复网格，水面没有海浪和金属感，雾不过浓。
- [ ] 连续播放无显著闪烁、降噪爬动、曝光抽动、树木重排或船只瞬移。
- [ ] 全部720帧可解码、尺寸相同、命名连续；视频分辨率、24 fps 与约30秒时长核对通过。
- [ ] 新开 Blender 能载入工程，无丢失贴图；随机抽帧可复现。
- [ ] 报告写清实际设备、版本、设置、耗时、降档与未完成项。

REPORT.md 的结论只对应实际看过的图像和视频。仅脚本退出码为0、文件存在或工程已保存，均不足以宣布画质验收通过。
